# Архитектура перехода на Spansh API

## Цель и границы

Убрать локальную галактическую БД, её первичный импорт, недельное обновление и HTML-скрейпинг EDSM. Приложение остаётся небольшим Rust CLI: получает исходную систему, ищет небесные тела вокруг её координат через Spansh, применяет критерии, группирует совпадения по родительским системам и выводит результат. Локальное постоянное хранилище не требуется.

## Текущее состояние ветки

- CLI вынесен в `src/cli.rs`; прежние короткие/длинные флаги и значения по умолчанию зафиксированы тестами.
- Новый сценарий подключён через `src/main.rs`; старый `src/parser` удалён.
- Реализованы слои `application`, `domain`, `presentation`, `spansh`.
- HTTP-клиент ограничивает параллелизм одним запросом и выдерживает интервал не менее одной секунды.
- Resolver использует exact match имени, затем fallback удалением конечных компонентов; координаты берёт прямо из search result, если они там есть.
- Body search использует `search_reference`/recall, а без reference — повторный POST с увеличенным `page`.
- Пагинация учитывает `count/from`, дедупликация выполняется по ID64, результаты группируются по `system_id64`.
- Удалены EDSM HTML-парсер и зависимости `scraper`, `futures`, `indicatif`, `urlencoding`.
- CI: `cargo fmt -- --check`, `cargo clippy --locked`, `cargo test --locked`.

## Обязательная совместимость CLI

Старая внутренняя реализация не является контрактом и может быть удалена целиком. Единственный обязательный контракт совместимости — интерфейс CLI из прежнего `src/main.rs`:

| Параметр | Короткий флаг | Длинный флаг | По умолчанию |
|---|---|---|---|
| Центральная система | `-S` | `--system` | обязательный |
| Тип поверхности | `-P` | `--planet-type` | обязательный |
| Тип атмосферы | `-A` | `--atmosphere-type` | обязательный |
| Температура | `-t` | `--temperature` | `0-5000` |
| Гравитация | `-g` | `--gravity` | `0.1-1.0` |
| Давление | `-p` | `--pressure` | `0.0-10.0` |
| Количество | `-c` | `--count` | `5` |

Сохранены допустимые прежние текстовые значения enum и формат диапазонов `min-max`. Новые параметры разрешены только как необязательные дополнения; существующие нельзя переименовывать или менять их значения по умолчанию.

## Целевая архитектура

```text
CLI / Args
  -> SearchUseCase
      -> SystemResolver
          -> GET /api/search/systems?q=<name>
          -> ResolvedSystem { id64, canonical_name, x, y, z }
      -> BodySearchQuery (reference_coords + radius)
      -> SpanshClient (HTTP, timeout, retry, 1 request/sec)
          -> POST /api/bodies/search
          -> GET /api/bodies/search/recall/{search_reference}/{page}
             OR POST /api/bodies/search with incremented page
      -> BodyNormalizer
      -> CriteriaEvaluator
      -> GroupBySystemId64
  -> CLI formatter
```

### Компоненты

1. **domain** — типы критериев, диапазоны, система, тело и результат. ID64 хранится как строка или `u64`, никогда как `f64`.
2. **spansh::client** — единственная точка HTTP-доступа: таймаут, ограниченные повторы для сетевых ошибок/429/5xx, один одновременный запрос и интервал не менее секунды между началами запросов.
3. **system resolver** — exact match по имени. Если точного совпадения нет, последовательно удаляет компоненты имени справа; на fallback выбирает первый результат API. Координаты берутся из `x/y/z` search result; если их нет — из `record` в `GET /api/system/{id64}`.
4. **query builder** — строит payload Spansh из координат и радиуса. Температура, давление, гравитация, subtype, атмосфера и статусы тела проверяются локально.
5. **pagination** — предпочитает recall по `search_reference`; если reference отсутствует, повторяет POST с `page=N`. Использует `count/from`, empty/short-page fallback и защитный лимит 100 страниц.
6. **normalizer/evaluator** — приводит nullable-поля к доменным типам и проверяет точные границы локально. Для атмосферы использует описательный label; если он равен `No atmosphere`, извлекает доминирующий газ из `atmosphere_composition[{name, share}]`. Отсутствующие числовые поля не превращаются в ноль.
7. **presentation** — группирует строго по `system_id64`; не содержит HTTP и бизнес-логики.

## Контракт Spansh: подтверждённое и требующее проверки

### Подтверждено live smoke-тестами

- `GET /api/search/systems?q=Sol` возвращает объект с `count`, `query`, `results`; элемент результата содержит `id64`, `name`, плоские `x/y/z`.
- `GET /api/system/{id64}` возвращает данные системы внутри `record`; внутри есть `id64`, `name`, `x/y/z`.
- `POST /api/bodies/search` принимает payload с `filters.distance`, `sort`, `size`, `page`, `reference_coords`.
- Ответ body search содержит `count`, `from`, `results`, `search`, `search_reference`, `size`.
- `search_reference` — UUID; `GET /api/bodies/search/recall/{reference}/1` вернул следующую страницу. Для выдачи `count=40` запрос страницы 39 вернул `from=39` и одну строку; условие `from + rows >= count` корректно распознало последнюю страницу.
- Повторный POST с `page=1` также вернул следующую страницу: `from` изменился с 0 на 1, ID64 тела отличался.
- В живом ответе тела наблюдались поля `name`, `id64`, `system_id64`, `system_name`, `subtype`, `distance`, `is_landable`, `is_mapped`, `surface_temperature`, `surface_pressure`, `gravity`, `atmosphere`, `atmosphere_composition`.
- Для Mercury поле `is_mapped` пришло как `null`; согласно legacy parser default, `null` трактуется как false (не отмечено как mapped).
- `atmosphere` — описательный label и иногда содержит `No atmosphere` даже при заполненном составе. `atmosphere_composition` — массив компонентов с долями: Venus CO2 96.5%, Earth Nitrogen 77.89%/Oxygen 20.89%, Io Sulphur dioxide 90%. Нормализатор проверен live: Venus -> Carbon dioxide, Earth -> Nitrogen, Io -> Sulphur dioxide.
- Радиус 100 ly вернул `count=10000`; page 40 — Alpha Centauri на 4.37712 ly. Первая страница размера 100 содержит landable Rocky body `2045 PC2` в Alpha Centauri; он проходит широкие локальные критерии после исключения Sol (85.062 K, pressure 0, gravity 0.0868 g, No atmosphere). Page 99 вернула `from=9900` и 100 строк — последняя страница 10k выдачи.
- Температуры наблюдались в Kelvin; gravity — в g. Значения pressure выглядят совместимыми с atm, но единица давления остаётся требующей независимой проверки.

Проверенные координаты: Sol `(0,0,0)`, радиусы 1 и 100 св. л.; recall pages 1, 39 и 99; direct POST page 1. Подтверждён поиск соседней системы с подходящей landable планетой и пагинация до 10 000 строк. Поведение свыше 10 000 и полный контракт API ещё требуют проверки.

### Ещё требуется проверить

- Точную семантику `distance` относительно `reference_coords` для разных систем.
- Единицы surface_pressure (предположительно atm) и consistency для разных типов тел; Kelvin и g подтверждены на нескольких Sol bodies.
- Все варианты `subtype` и `atmosphere` и их соответствие старым CLI enum.
- Поведение свыше 10 000 результатов и точный provider cap; максимальный размер страницы выше 100.
- Поведение 400, 429, 5xx, таймаутов и временно недоступного recall reference.
- Полноту/актуальность данных Spansh.

## Поток запроса

1. Валидировать аргументы CLI и диапазоны (finite, min <= max).
2. Разрешить имя центральной системы: точное совпадение, затем fallback по компонентам имени.
3. Получить координаты центра и ID64; при наличии координат в search result не запрашивать system detail.
4. Сформировать body search с координатами и радиусом (по умолчанию 100 св. л.).
5. Получать страницы через recall или повторный POST; определить конец по `count/from`, пустой/короткой странице или флагу сервера.
6. Нормализовать тела и дедуплицировать по `body_id64`; fallback — составной ключ родительской системы и имени тела.
7. Исключить центральную систему по system_id64 (если ID64 отсутствует — по имени), затем проверить радиус и пользовательские критерии локально. Только `is_mapped=true` исключает тело; `false/null` считается неотмеченным как mapped.
8. Группировать строго по `system_id64`; сортировка запроса — `distance ASC`, но ближайший порядок пока не подтверждён на большой выдаче.
9. Остановиться после набора требуемого количества совпадений или подтверждённого конца страниц.

## Отказы и эксплуатация

- Не хранить dump и не запускать background importer.
- Все запросы имеют timeout.
- Один одновременный запрос и интервал не менее секунды между началами запросов.
- Повторять только временные ошибки с ограниченной экспоненциальной задержкой.
- Не скрывать ошибки нормализации/сетевого запроса через `.ok()`; ошибка не должна превращаться в ложный «0 результатов».
- Защитный предел — 100 страниц по 100 тел (до 10 000 записей); live выдача 100 св. л. вернула ровно 10 000. Достижение лимита до подтверждённого конца возвращает ошибку потенциально неполной выдачи.
- Spansh — внешний источник: отсутствие/устаревание данных отражается в документации и сообщениях.

## Текущие технические параметры реализации

- Радиус поиска по умолчанию: 100 св. л. (временная константа, старый CLI не имел параметра радиуса).
- Размер страницы: 100; защитный предел: 100 страниц.
- Параллелизм Spansh HTTP-клиента: 1.
- Минимальный интервал между HTTP-запросами: 1 секунда, включая повторы.
- На сервер отправляются координаты центра и фильтр расстояния; физические критерии перепроверяются локально.
- Если `search_reference` отсутствует, используется подтверждённый direct POST с увеличенным `page`.
- `count/from` используются для обнаружения последней страницы; если metadata отсутствует, применяется empty/short-page fallback.
- Локальная проверка радиуса требует числового поля расстояния у каждого принятого тела.
