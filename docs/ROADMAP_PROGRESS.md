## Правила фиксации

- Этапы 0–8 выполняются строго последовательно.
- Задачи внутри этапа оформляются отдельными коммитами.
- Этап не закрывается до прохождения его критериев приёмки.
- Неизменны доменная логика экзобиологии, правила фильтрации, пресеты, пагинация и повторы Spansh.
- Работа ведётся в указанной владельцем ветке `ed-ps-new-horizon`. Указанная в ROADMAP ветка `refactor/tui-cleanup` не создаётся, поскольку рабочая ветка явно задана владельцем.

## Журнал

### Этап 2 — типизированный каталог, критерии и форма

- Добавлен `src/domain/catalog.rs`: 5 `SurfaceType`, 17 `AtmosphereType`, канонические значения Spansh, русские подписи и `FromStr` для прежних вариантов CLI. Round-trip и legacy-значения проверяются таблично.
- `SearchCriteria` переведён на `Filter<T> { Any, OneOf(Vec<T>) }`; `matches()` сохраняет OR-поверхности, `any`, числовые ограничения, landable/unmapped и исключение биосигналов. Удалены строковые поля и `from_cli`.
- `SearchPreset` хранит enum-значения; `to_criteria()` доступен в production, а гравитация вынесена в `PRESET_GRAVITY_RANGE`.
- Добавлен `application/form.rs`: `SearchForm`, `apply_preset`, `from_config`, русское `summary()` и `build()` с набором `FieldError`, привязанных к `FormField`. Модуль не зависит от Ratatui.
- CLI и старый мастер направлены через `SearchForm`; диапазоны разбираются общими функциями из `cli.rs`, локальная копия из `setup.rs` удалена. Табличный CLI-тест проверяет `any`, canonical values, legacy aliases, диапазоны и bio-флаг.
- Добавлены тесты round-trip `from_config`, применения профиля с сохранением system/count/bio, полей ошибок и русских подписей. Семантика `any` и OR дополнительно зафиксирована до миграции.
- В ходе проверки исправлены два регрессионных риска: накопление ошибок диапазонов (включая обратный диапазон) и сохранение старых методов навигации мастера при переводе его на `SearchForm`.


### Этап 2 — характеризующие тесты перед изменением модели

- Подтверждены существующие тесты на legacy-нормализацию CLI, все прежние значения поверхности/атмосферы, OR-поверхности и исключение по биосигналам.
- Добавлен отдельный тест семантики `any`: неизвестные и отсутствующие subtype/atmosphere не ограничивают поиск, но числовые диапазоны, landable и unmapped ограничения продолжают действовать.
- OR-тест расширен: оба разрешённых типа поверхности проходят, третий — нет.
- GitHub Actions `Rust CI`, run `44987128953`: fmt, Clippy и тесты зелёные; 71 unit + 5 catalog passed, 1 live ignored.

### Этап 1 — задача 4: достижимость ветки mapped

- Ветка `body.is_mapped == Some(true)` в `draw_results` достижима: `Body::from_json` читает `is_mapped`/`mapped`, а fixture `tests/fixtures/spansh/body-search-page-0.json` содержит запись с `is_mapped: true`. На странице 1 есть `is_mapped: false`, то есть покрыты оба значения.
- Ветка не удалялась: условие отображения метки и зелёного стиля не является мёртвым кодом. Дополнительное изменение не требуется.

### Этап 1 — задача 3: тесты поведения вместо тестов реализации

- Три теста CLI-парсинга флагов объединены в один табличный тест; отдельные проверки преобразования в `SearchConfig` и отклонения перевёрнутого диапазона сохранены.
- Проверки обрезки пробелов и пустого имени системы объединены; проверка нулевого количества сохранена.
- Повторяющиеся retry-кейсы 503 и 429 объединены в один табличный тест; исчерпание retry-бюджета и отсутствие retry для 400 сохранены.
- В `spansh/system.rs` объединены похожие случаи exact candidate, first candidate и detail parser в таблицы; три HTTP-сценария переведены на общий `MockServer`. Проверка URL-кодирования удалена как отдельная проверка приватного помощника: кодирование проверяется в тесте реального запроса resolver.
- Из `spansh/bodies.rs` удалены тесты значения константы радиуса и приватного helper-а исключения центральной системы. Радиус 1000 св. лет теперь проверяется в фактическом POST payload; исключение центрального тела проверяется сквозным поисковым тестом. Пагинация, recall, fallback, истёкшая ссылка, лимит страниц и разбор ответов сохранены.
- Табличный тест `application/presets.rs` теперь дополнительно проверяет, что все семь пресетов дают ожидаемые `SearchCriteria`, включая OR-типы поверхности, давление, температуру, гравитацию и bio-флаг. Реализация `SearchPreset::criteria` не менялась.
- Проверка: GitHub Actions `Rust CI`, run `44986831402` — fmt, Clippy и тесты зелёные; 70 unit + 5 catalog тестов прошли, один live-тест ignored (75 passed / 1 ignored). TTY run `44986831401` успешен на 120×40, 80×24 и 60×18.

### Этап 1 — задача 2: единый MockServer

- Удалены локальные реализации `TcpListener`/`read_request`/`respond` из `src/spansh/bodies.rs`, `src/spansh/client.rs` и `src/application/search.rs`; все эти тесты используют общий сервер.
- Сохранены проверки содержимого POST, recall GET, fallback POST, истёкшего recall GUID, retry для 429/503, отказа retry для 400, лимита страниц и минимального интервала запросов.
- Проверка: GitHub Actions `Rust CI`, run `44986304616` — форматирование, Clippy и все тесты прошли; 83 + 5 тестов успешно, 1 live smoke-тест ignored (88 passed / 1 ignored). TTY workflow run `44986304614` успешно проверил размеры 120×40, 80×24 и 60×18.
- Общие тестовые серверы теперь сосредоточены в одном файле; в трёх исходных файлах больше нет `TcpListener` и `read_request`.

### Этап 1 — задача 1: live-тесты Spansh

- Из `src/spansh/bodies.rs` удалены четыре `#[ignore]` live-теста: `live_spansh_body_search_contract`, `live_drojia_carbon_dioxide_rocky_query`, `live_spansh_radius_1000_named_systems`, `live_spansh_water_atmosphere_diagnostic`.
- `live_spansh_body_search_contract` сохранён в `tests/live_spansh.rs` как ручной интеграционный smoke-тест; три целевые диагностики конкретных систем удалены согласно плану.
- Для настоящего интеграционного теста добавлена библиотечная точка входа `src/lib.rs`; бинарник теперь использует библиотечные модули. CLI экспортирует `parse_args()`, внутренний `Args` остаётся скрытым. Это устраняет повторное компилирование и выполнение unit-тестов внутри интеграционного теста.
- **Ruling:** добавлен `src/lib.rs` вместо подключения исходных модулей через `#[path]` в интеграционном тесте — проект изначально имел только binary target, а прямое включение модулей дублировало 60 unit-тестов. Стоимость ошибки: часть модулей становится публичным API; при необходимости их можно позже сузить через фасадные экспорты.
- Проверка: GitHub Actions `Rust CI`, run `44985731948` — `cargo fmt -- --check`, Clippy и `cargo test --locked --all-targets` успешны; тесты: 82 + 5 прошли, 1 live-тест ожидаемо ignored (всего 87 passed / 1 ignored). TTY workflow run `44985731943` успешен на 120×40, 80×24 и 60×18.
- Во время работы CI поймал форматирование и два варианта неверной компоновки модулей; все причины установлены по логам, исправления проверены последующими прогонами. Промежуточный вариант с `#[path]` отозван, поскольку приводил к дублированию тестов.

### Инициализация

- Прочитан `docs/ROADMAP.md`, включая архитектурные ограничения, макеты экранов, этапы 0–8, политику тестов, документации и открытые вопросы.
- Проверена структура репозитория на целевой ветке: исходное приложение пока содержит старую структуру `presentation/{setup,tui,output}.rs`; новых модулей целевой архитектуры ещё нет.
- Подтверждено, что `Cargo.toml` пока включает `tokio` features `net` и `io-util`, а live workflow привязан к устаревшей ветке `refactor/spansh-api-architecture` и диагностическому тесту.
- Гейт базовой линии подтверждён зелёным CI на неизменённом исходном коде (run `44984103574`). Отдельный TTY workflow добавлен в `.github/workflows/tty-diagnostics.yml`; он проверяет stdin/stdout TTY, запускает приложение в псевдотерминале с тремя размерами, сохраняет ANSI-логи и список тестов как артефакт. Успешный прогон: `44984764463`; артефакт ID `14738583754`. Первая попытка `44984705043` завершилась по тайм-ауту из-за неверно экранированного ESC в тестовом вводе; исправленный повтор прошёл все три размера. Из лога 120×40 видно, что текущий экран профилей корректно отрисовывается. На 60×18 интерфейс также рисуется, но отдельного сообщения о минимальном размере пока нет — это наблюдение для будущего этапа UI, не блокер базовой линии.
- Ограничение среды: локальный TTY отсутствует, но требуемая проверка заменена воспроизводимым GitHub Actions псевдотерминалом. Тег `baseline-before-refactor` остаётся единственным незакрытым пунктом: доступные GitHub-инструменты поддерживают чтение Git refs и создание веток, но не создание тегов.

## Открытые решения владельца

До отдельного указания применяются значения по умолчанию из ROADMAP: CLI-флаги не смягчать; отметку ★ удалить; радиус 1000 св. лет оставить фиксированным, последний поиск не сохранять; процессную документацию удалить на этапе 8; интерфейс оставить русскоязычным.
