# Оценка экзобиологии

## Назначение

Модуль `domain::exobiology` сопоставляет параметры планеты со справочником видов и показывает кандидатов для предварительной оценки потенциальной выручки. Это подсказка для выбора планет, а не гарантия наличия организмов или выплаты.

Данные справочника хранятся отдельно в `data/exobiology/species-v1.json` и включаются в бинарный файл на этапе сборки. Версия формата — 1, валюта — CR. Цены и условия происходят из ссылок, перечисленных в метаданных JSON.

## Как формируются кандидаты

Для каждого вида движок проверяет известные поля планеты:

- тип планеты (`subtype`);
- атмосферу;
- температуру поверхности в K, включая условные температурные правила;
- максимальную гравитацию и включительность границы;
- тип вулканизма, если он задан для вида;
- наличие геологических сигналов, если они требуются правилом.

Если известное значение противоречит правилу, вид исключается. Если нужное значение отсутствует, кандидат сохраняется со статусом «требует проверки» и списком неизвестных условий. Отсутствующее поле не считается подходящим значением.

Если Spansh передал список биологических групп, кандидаты ограничиваются этими группами. Если число биологических сигналов равно нулю, кандидаты не выводятся. Если сигналы есть, но список групп отсутствует, кандидатам добавляется неизвестное условие — точный состав групп.

В пользовательском интерфейсе таксономические роды называются биологическими группами. Названия групп переводятся на русский; видовые эпитеты остаются латинскими.

## Стоимость и ограничения оценки

- Для каждого вида в каталоге указана базовая стоимость полного набора из трёх образцов.
- Внутри одной биологической группы на планете учитывается не более одного вида. Поэтому верхняя граница группы — максимальная стоимость среди её кандидатов, а не сумма всех видов.
- Нижняя граница общей оценки сейчас равна 0 CR: предварительный прогноз не подтверждает, что какая-либо группа действительно присутствует.
- Верхняя граница — сумма максимальных стоимостей по перечисленным группам. Она предполагает, что каждая такая группа может присутствовать; это теоретический предел по текущему каталогу.
- First Logged показывается отдельным условным сценарием с множителем ×5. Он не применяется к обычной базовой оценке и не гарантируется.
- Вероятности появления видов не рассчитаны: в каталоге `probabilities` равно `null`, а оценка помечается `probabilities_calculated = false`. Равномерные или иные выдуманные вероятности не используются.
- Каталог явно помечен как неполный (`catalog_is_complete = false)); отсутствие кандидата не доказывает отсутствие биологии.

## Что пока не учитывается как проверенное условие

Текущая реализация не фильтрует виды по давлению поверхности или классу звезды. Некоторые правила каталога содержат ограничения по рельефу, но поскольку соответствующие сведения не подтверждены в модели планеты, кандидат помечается как требующий проверки. Дополнительные условия системы и тела также не считаются подтверждёнными автоматически.

First Footfall не используется как доказательство бонуса First Logged. Данные о фактическом сборе и журнал игрока не подключены.

## Проверка и развитие

Основные правила покрываются тестами в `src/domain/exobiology.rs`: различение Water и Water-rich, границы температуры и гравитации, неизвестный вулканизм, сужение по известным биологическим группам и подавление кандидатов при нуле биосигналов.

При расширении каталога необходимо:
1. обновлять versioned JSON и его источники;
2. сохранять неизвестные условия как «требует проверки», пока соответствующие данные не поступают из достоверного источника;
3. не суммировать альтернативные виды одной биологической группы;
4. не добавлять вероятности без датасета наблюдений и проверки качества калибровки;
5. сохранять First Logged как отдельный условный сценарий.
