## 1. Диагноз ветки feature/interactive-terminal-ui

Приложение — Rust-утилита (edition 2024, ratatui 0.29) для поиска планет в Spansh с расчётом экзобиологии: около 7,1 тыс. строк кода, из них около 3,3 тыс. строк — тесты. Отдельно лежат 13 файлов документации (1,4 тыс. строк), в основном о процессе разработки. Главная проблема — не алгоритмы, а интерфейс и «слои истории»: три поколения UI-документов, два набора терминальных утилит и тесты, которые охраняют промежуточные решения.

Снимок получен клонированием ветки (HEAD 2ef8eeb); сборка и тесты в этой среде не запускались (нет сети для зависимостей), поэтому этап 0 обязан зафиксировать базовую линию.

### Что здесь хорошо и не должно ломаться

- Слои `domain` / `spansh` / `application` разделены разумно; рефакторинг касается в основном `presentation` и границы с `domain::criteria`.
- Доменные тесты (`criteria.rs`, `body.rs`, `exobiology.rs`) и тест каталога `tests/exobiology_catalog.rs` описывают бизнес-правила и сохраняются.
- Семь пресетов с точными числами, OR-логика типов поверхности для профиля 3, независимость переключателя биосигналов, «вулканизм не фильтр» — зафиксированные требования владельца; менять только по явной просьбе.
- CI: `fmt`, `clippy -D warnings`, `cargo test --locked --all-targets` — оставить как гейт.

## 2. Целевая архитектура и правила для агента

Слои остаются прежними; меняется только `presentation/`: вместо двух циклов с собственной отрисовкой — одно состояние, одна функция `update` и чистый `render`. Доменная логика и клиент Spansh не переписываются.

&#91;embedded content: поток событий TUI · 6 компонентов\]

Клавиши и результаты фонового поиска попадают в один канал; `update` — единственное место, где меняется состояние, а поиск запускается командой, а не из обработчика клавиш.

### Раскладка модулей

```text
src/
  main.rs                 CLI → tui::run(initial_config)
  cli.rs                  флаги min-max → SearchConfig (только разбор строк)
  domain/
    catalog.rs            SurfaceType, AtmosphereType            (новое)
    criteria.rs           SearchCriteria, matches()
    body.rs, exobiology.rs    без изменений
  spansh/                 клиент, запросы, DTO; + колбэк прогресса
  application/
    config.rs, presets.rs
    form.rs               SearchForm → SearchConfig               (новое)
    search.rs             SearchUseCase + SearchEvent
  presentation/
    terminal.rs           TerminalGuard + panic hook              (новое)
    theme.rs, text.rs     палитра, русские строки                 (новое)
    app.rs, events.rs     состояние, update(), поток событий      (новое)
    screens/{search,running,results,error}.rs                     (новое)
    widgets/text_input.rs                                         (новое)
```

### Правила для агента

1. **Направление зависимостей:** `presentation` → `application` → `domain` и `spansh`. `domain` ничего не знает о других слоях; `presentation` не обращается к `spansh` напрямую.
2. **Состояние меняется только в `update`;** `render` его читает. Сеть, файлы и терминал внутри `update` запрещены.
3. **Не менять:** алгоритм `domain/exobiology.rs`, пагинацию и повторы в `spansh/`, числа пресетов, правило «вулканизм не фильтр». Любой отход от этого — вопрос владельцу.
4. **Один коммит — одна задача** (одна строка чекбокса из раздела 4); заголовок коммита по-английски в повелительном наклонении, как в текущей истории.
5. **Новые зависимости только по плану** (`base64` на этапе 6). Сеть в среде агента может быть закрыта: если пакет не скачивается, реализовать функцию вручную и написать об этом в PR.
6. **Выполнение отмечать в описании PR** списком задач этапа; расхождения с планом и принятые значения по умолчанию из раздела 6 — отдельным абзацем.
7. **Если задача не помещается в этап** или противоречит правилам выше, остановиться и вернуть вопрос, а не расширять объём.

## 3. Новый интерфейс: три экрана вместо мастера на четыре шага

Пользователь должен дойти от запуска до списка планет одним нажатием Enter: сценарий выбран заранее, система уже заполнена, а всё, что требует тонкой настройки, спрятано в «Дополнительно». Сейчас для первого поиска нужно пройти четыре шага и открыть минимум два модальных окна.

### Принципы

1. **Один экран настройки.** Выбор сценария мгновенно заполняет форму справа, подтверждения «Enter, чтобы применить профиль» нет.
2. **Три основных поля:** система, сколько планет, скрывать ли планеты с биосигналами. Остальное (поверхность, атмосфера, температура, гравитация, давление) раскрывается клавишей F2 и редактируется прямо в строке, а не в модальном окне.
3. **Числа с единицами и раздельные поля мин/макс** вместо строки `190-195`. Ошибка показывается красным под полем, поиск не стартует, введённое не теряется.
4. **Понятные названия.** В интерфейсе русские подписи; внутри домена остаются английские значения Spansh, подпись и значение связываются одним справочником (этап 2).
5. **Сдержанная палитра:** один акцентный цвет, три статусных (успех, предупреждение, ошибка) и один приглушённый. Никаких разноцветных рамок у каждой панели.
6. **Подсказки клавиш — одна строка внизу, не более пяти действий;** полный список по `?`. Буквенные команды дублируются кириллицей (c/с, s/ы, n/т), чтобы не зависеть от раскладки.
7. **Никаких скрытых режимов:** сортировка выбирается клавишей `s` и отмечается стрелкой в заголовке столбца.
8. **Минимум 80×24;** меньше — одно понятное сообщение «Увеличьте окно терминала». При ширине меньше 100 колонок панель подробностей уходит под таблицу.
9. **Каждый тупик имеет выход:** пустой результат и ошибка предлагают «изменить поиск» и «повторить».

### Экран 1. Поиск

```text
┌ ED Planet Search ───────────────────────────────────────────────┐
│ Сценарий                       Параметры                         │
│ ▸ CO₂ · скалы · 190–195 K      Система        Sol_______         │
│   CO₂ · скалы · 180–190 K      Сколько        5                  │
│   Вода · скалы и металл        Без биосигналов [ ]               │
│   …ещё 4 сценария              ▸ Дополнительно (F2)              │
│   Свой поиск                                                     │
│ ─────────────────────────────────────────────────────────────── │
│ Ищем: каменные планеты · CO₂ · 190–195 K · 0.1–1.0 g · 5 шт.     │
│       в радиусе 1000 св. лет от Sol                              │
│ ─────────────────────────────────────────────────────────────── │
│ Enter искать · Tab поле · F2 дополнительно · ? помощь · Esc выход│
└──────────────────────────────────────────────────────────────────┘
```

Строка «Ищем:» — живая сводка критериев; она заменяет отдельный шаг «Проверка». Справа от сценария показываются его справочные числа (число дорогих видов, потенциал в CR) только как подсказка, не как фильтр.

### Экран 2. Поиск идёт

```text
┌ Поиск ──────────────────────────────────────────────────────────┐
│ ✓ Система найдена: Sol                                           │
│ ● Загружаю данные Spansh, страница 3                             │
│   Найдено подходящих: 2 из 5                                     │
│                                                                  │
│ Esc отменить поиск                                               │
└──────────────────────────────────────────────────────────────────┘
```

Прогресс берётся из событий фоновой задачи (этап 5), а не из таймера; интерфейс не блокируется.

### Экран 3. Результаты

```text
┌ Найдено 5 · Sol · CO₂ · скалы ───────────────────────────────────┐
│ Планета           Система          св.л.▲  K     atm    g   Выручка│
│ ▸ A 3             Sol Sector AB     12.4  193  0.060  0.41  36 млн │
│   B 1             Alpha Sector XY   31.0  191  0.052  0.38  21 млн │
│ ───────────────────────────────────────────────────────────────── │
│ A 3 · Rocky body · CO₂                                             │
│ Биосигналы Spansh: 0   Виды: 4 подходят, 2 проверить               │
│  Bacterium Cerbrus   1.69 млн · подходит                           │
│ ───────────────────────────────────────────────────────────────── │
│ ↑↓ выбор · c копировать систему · s сортировка · e изменить · ? ...│
└────────────────────────────────────────────────────────────────────┘
```

Ключевые изменения: в таблице сразу видны система, расстояние и условия; панель подробностей всегда открыта под таблицей; `c` копирует имя системы (то, что игроку нужно для прокладки маршрута); `n` — новый поиск, `e` — изменить критерии с сохранением введённого. Таблица экзобиологии рисуется виджетом ratatui `Table`, а не ASCII-текстом из `render_table`.

### Опционально (этап 7, по решению владельца)

- Запоминать последний поиск в файле конфигурации пользователя.
- Сделать радиус редактируемым полем в «Дополнительно». Сейчас он зашит в 1000 св. лет и спецификация прямо запрещает менять его без отдельного требования.

## 4. Дорожная карта: девять этапов, строго по порядку

Каждый этап — отдельный PR в рабочую ветку `refactor/tui-cleanup`, созданную от `feature/interactive-terminal-ui`; внутри этапа — по одному коммиту на задачу. Переход к следующему этапу разрешён только при зелёном гейте:

```bash
cargo fmt -- --check && cargo clippy --locked --all-targets --all-features -- -D warnings && cargo test --locked --all-targets
```

Этапы 1–2 не меняют внешнее поведение вообще; этапы 3–6 меняют только `presentation/`; доменная логика поиска и экзобиологии не меняется нигде.

## 5. Чистка тестов и документации

Сейчас в проекте 91 тест; около 80 % строк `spansh/bodies.rs` — тесты, причём четыре из них ходят в реальный Spansh. Цель — не уменьшить число любой ценой, а оставить тесты, которые падают, когда ломается поведение для пользователя.

### Правила для агента

1. **Оставить**, если тест защищает правило из раздела «Сохранение поведения» (пресеты, OR-типы поверхности, биосигналы, вулканизм не фильтр), разбор реального контракта Spansh или переход состояния, видимый пользователю.
2. **Удалить или свернуть**, если тест проверяет приватный помощник, повторяет другой тест с другими числами, сверяет символы рамок и вёрстку ASCII, проверяет значение константы или разово диагностирует одну систему.
3. **Однотипные тесты — в один табличный:** массив случаев и цикл с понятным сообщением о случае.
4. Перед удалением записать в описание PR: имя теста, причину и где то же поведение защищено теперь. Если поведение нигде больше не защищено, тест не удалять.
5. Нельзя удалять или ослаблять тест, чтобы позеленить гейт; падающий тест сначала объясняется.
6. Моки HTTP — только через общий `MockServer` (этап 1); копировать `TcpListener` в новый тест запрещено.
