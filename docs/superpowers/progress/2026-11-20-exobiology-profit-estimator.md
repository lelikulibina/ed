# Прогресс реализации прогноза экзобиологии

Дата: 2026-11-20  
Ветка: `refactor/spansh-api-architecture`

## Выполнено

- Добавлен версионируемый JSON-справочник `data/exobiology/species-v1.json`.
- В справочник включены проверенные записи для Osseus Discus, Tussock Virgam/Stigmasis, Cactoida Vermis, Clypeus Lacrimam/Margaritus, Recepta Deltahedronix и Bacterium Cerbrus.
- Добавлен доменный движок `src/domain/exobiology.rs`.
- Правила сопоставления используют известные поля текущего `Body`: subtype, atmosphere, surface_temperature (K), gravity.
- Несовпадающие известные ограничения исключают вид; отсутствующие данные оставляют его кандидатом с пометкой о проверке.
- Ограничения вулканизма сохраняются в справочнике, но пока помечаются как неизвестные: фактическое поле Spansh не подтверждено и в `Body` не добавлено.
- Альтернативные виды одного рода агрегируются через min/max, а не суммируются.
- Нижняя граница по планете равна нулю до подтверждения биологических сигналов; верхняя граница суммирует максимум каждого возможного рода.
- First Logged отображается отдельным условным сценарием ×5. Вероятности не выдумываются.
- Предварительная оценка добавлена в вывод результатов поиска.
- Добавлены интеграционные и доменные тесты на справочник, границы правил, неизвестный вулканизм, альтернативы рода и First Logged.

## Ограничения и решения

- Официальная документация Spansh подтверждает endpoint `GET /body/{id64}`, но доступная схема документации не раскрыла контракт полей биосигналов, вулканизма, звёздного контекста и First Footfall.
- Решение: не угадывать имена полей и не добавлять их в DTO до получения реального ответа API/fixture. До этого Bacterium Cerbrus остаётся кандидатом «требует проверки», а не подтверждённым совпадением.
- Поиск планет и его фильтры не менялись.
- Давление не используется в видовых правилах, если справочник не задаёт такое ограничение.
- Температура остаётся в Кельвинах без преобразований.
- Численный expected value не реализован: нет калиброванного датасета вероятностей.

## Проверки

- CI выполняется через GitHub Actions после каждого коммита.
- Последний проверенный успешный прогон до включения движка: коммит `318d4b9` — только каталог и его тесты; доменный модуль на том коммите ещё не был подключён.
- Полная проверка доменного движка и вывода ожидает завершения актуального Rust CI. Не считать реализацию проверенной до успешного прогона `cargo fmt`, Clippy и `cargo test`.
