# Прогресс реализации прогноза экзобиологии

Дата: 2026-11-20  
Ветка: `refactor/spansh-api-architecture`

## Выполнено

- Добавлен версионируемый JSON-справочник `data/exobiology/species-v1.json`.
- Справочник расширен до 76 записей по 14 родам: Aleoida, Bacterium, Cactoida, Clypeus, Concha, Fonticulua, Frutexa, Fumerola, Fungoida, Osseus, Recepta, Stratum, Tubus и Tussock. Он покрывает виды для основных атмосфер из пользовательских профилей, но всё ещё не является полным каталогом.
- Добавлен доменный движок `src/domain/exobiology.rs`.
- Правила сопоставления используют поля `Body`: subtype, atmosphere, surface_temperature (K), gravity и volcanism_type.
- Парсер поддерживает контракт Spansh `SearchBody` (snake_case) и dump `Body` (camelCase): biological/geological signal count, genuses, signals update time, volcanism type.
- `genuses` нормализуются из API-имён (`Bacterial`, `Tussocks`, `Cactoids`) и Codex-токенов в имена родов справочника.
- Несовпадающие известные ограничения исключают вид; отсутствующие данные оставляют его кандидатом с пометкой о проверке.
- Ограничения вулканизма сопоставляются с официальным enum Spansh, включая точное значение `No volcanism` и конкретные типы магмы/гейзеров. Отсутствующее поле остаётся неизвестным, а не автоматически приравнивается к отсутствию вулканизма.
- Для видов, требующих определённого рельефа или фумарол, кандидат остаётся помеченным как требующий проверки: в `SearchBody` нет достаточного поля terrain. Наличие geological signals используется как предварительный фильтр, но не доказывает наличие нужной фумаролы.
- Добавлены атмосферно-зависимые температурные правила, чтобы температурные пределы применялись только к тем атмосферам, для которых они указаны в источнике.
- Биологический signal count берётся только из `signals` по типу `Biological`; общий `signal_count` не используется вместо него. Если Spansh возвращает ноль биологических сигналов, прогноз видов подавляется. Если список родов доступен, кандидаты ограничиваются этими родами.
- Альтернативные виды одного рода агрегируются через min/max, а не суммируются.
- Нижняя граница по планете равна нулю до подтверждения биологических сигналов; верхняя граница суммирует максимум каждого возможного рода.
- First Logged отображается отдельным условным сценарием ×5. Вероятности не выдумываются.
- Предварительная оценка добавлена в вывод результатов поиска. Вывод явно предупреждает, что кандидаты совпадают только по внесённым в справочник условиям и полный набор игровых условий пока не моделируется.
- Добавлены интеграционные и доменные тесты на справочник, границы правил, неизвестный вулканизм, альтернативы рода, First Logged и оба формата Spansh biology metadata.

## Ограничения и решения

- Контракт подтверждён официальными схемами Spansh: [api.openapi.json](https://github.com/spansh/elite_dangerous_schemas/blob/9355a09c054ebf0975a1e662a62dec46b303e990/api.openapi.json) и [model.openapi.json](https://github.com/spansh/elite_dangerous_schemas/blob/9355a09c054ebf0975a1e662a62dec46b303e990/model.openapi.json).
- `GET /body/{id64}` возвращает `{record: SearchBody}`. В `SearchBody` есть `volcanism_type`, `signals[{name,count}]`, `signal_count`, `signals_updated_at`, `genuses[{name}]` и `landmarks`.
- Dump `Body` использует camelCase: `volcanismType`, `signals.signals` с ключом `$SAA_SignalType_Biological;`, `signals.genuses` с Codex-токенами и `signals.updateTime`.
- В Spansh-модели не обнаружены достоверные поля First Footfall или First Logged. Эти признаки нельзя выводить из `is_mapped`, `landmarks` или отсутствия сигналов; для них потребуется отдельный источник/журнал.
- `parents` доступны в модели тела, но полноценный контекст главной звезды требует связать цепочку родителей с телами из system dump; пока не используется, так как текущая выборка видов не требует star rules.
- Поиск планет и его фильтры не менялись.
- Предпочтительные места обитания не превращаются в жёсткие ограничения: для Tussock и Cactoida поле `planet_types` оставлено пустым, если источник описывает только предпочтение/типичную среду.
- Давление не используется в видовых правилах, если справочник не задаёт такое ограничение.
- Температура остаётся в Кельвинах без преобразований.
- Численный expected value не реализован: нет калиброванного датасета вероятностей.
