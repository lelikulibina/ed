# Единый TUI для настройки, поиска и результатов

**Статус:** согласовано к реализации по запросу пользователя.
**Рабочая ветка:** `feature/interactive-terminal-ui`

## Цель

Сделать TUI единственным пользовательским интерфейсом приложения. Один и тот же полноэкранный интерфейс используется для настройки критериев, выполнения поиска, отображения результатов и просмотра подробностей планет. Старый построчный вывод результатов удаляется.

## Сценарии запуска

- Запуск без аргументов в интерактивном терминале: сразу открыть TUI на экране выбора профиля/ручной настройки.
- Запуск с аргументами поиска: разобрать аргументы, выполнить поиск без экрана настройки и открыть тот же TUI сразу на экране результатов. Значения из CLI не должны запускать старый текстовый вывод.
- `--help` и `--version` остаются стандартными служебными режимами Clap.
- Если требуется показать результаты, но stdout не является TTY, завершиться с понятной ошибкой о необходимости интерактивного терминала. Не возвращать старую форму вывода.

## UX

Единая оболочка с постоянной шапкой, основной областью, контекстной боковой панелью и строкой подсказок клавиш. Основные состояния:
1. Настройка: список семи профилей, ручная конфигурация и сводка критериев.
2. Выполнение: состояние разрешения центральной системы, отправки запроса, загрузки страниц и завершения; интерфейс остаётся отзывчивым.
3. Результаты: список найденных планет, выбор строки, сортировка/навигация и подробная панель выбранного тела.
4. Ошибка/пустой результат: объяснение и действия «повторить», «изменить критерии», «назад».

Единая навигация и независимый фокус областей. Редактируемые поля должны поддерживать курсор, вставку и удаление текста, а не только добавление в конец.

## Прикладная архитектура

- Ввести единый объект конфигурации поиска, который создаётся как из TUI, так и из CLI.
- Вынести преобразование конфигурации в SearchCriteria и валидацию из отрисовки.
- TUI владеет состоянием приложения и получает события выполнения поиска.
- Сетевой поиск выполняется в фоновой Tokio-задаче; события доставляются в TUI через канал, чтобы ввод и перерисовка не блокировались.
- События минимум: разрешение системы, найденный центр, начало загрузки/страницы, завершение с результатами, ошибка.
- Существующие SearchUseCase, BodySearch, Spansh-парсинг, доменные фильтры и расчёт экзобиологии сохраняются; добавляется только необходимая публикация событий.
- Представление результатов переносится в Ratatui. Содержимое карточки/подробностей переиспользует существующий расчёт экзобиологии, но не старый println-рендерер.

## Сохранение поведения

- Сохранить семь профилей и все их точные значения.
- Температура остаётся в K, давление в atm, гравитация профилей 0.1–1.0 g.
- Альтернативы типов поверхности профиля №3 остаются OR.
- Вулканизм не становится фильтром.
- Исключение тел с зарегистрированными биосигналами остаётся независимым переключателем.
- Число дорогих видов и потенциальная стоимость остаются справочной информацией.
- Алгоритм фильтрации и интерпретация данных Spansh не меняются.

## Не входит в задачу

- Не менять источник данных и радиус поиска без отдельного требования.
- Не переписывать доменную модель планеты или каталог экзобиологии.
- Не поддерживать старый текстовый формат выдачи как второй режим.
- Не делать TUI зависимым от CLI: оба интерфейса ввода создают общую конфигурацию.

## Подходы и решение

1. Оставить старый вывод для CLI и добавить TUI только для интерактивного режима — отклонён, поскольку сохраняет два разных пользовательских интерфейса.
2. Сделать TUI обязательным, но запускать поиск только из интерактивной формы — отклонён, поскольку CLI-аргументы теряют смысл для быстрого запуска.
3. Единый TUI и для интерактивного выбора, и для просмотра результатов; аргументы CLI запускают тот же поиск и открывают TUI сразу с результатами — выбран пользователем. Это сохраняет автоматизированный запуск параметрами и устраняет устаревший вывод.

## Критерии приёмки

- Любой успешный поиск отображается в Ratatui, независимо от способа задания критериев.
- Нет вызовов старого построчного print_results в пользовательском потоке.
- UI продолжает принимать клавиши и перерисовываться во время сетевого поиска.
- Пользователь может выбрать планету и увидеть её параметры и расчёт экзобиологии.
- Из результатов можно вернуться к критериям и запустить новый поиск.
- CLI-параметры дают те же SearchCriteria, что и раньше.
- Тесты покрывают конфигурацию, переходы состояний, события поиска и отображение пустых/успешных результатов.
- `cargo fmt -- --check`, Clippy с `-D warnings` и `cargo test --locked --all-targets` проходят.
