# Полная замена внутреннего поиска на Spansh — план реализации

> **Для исполнителя:** выполнять задачи последовательно с TDD; каждая задача должна иметь собственную проверку.

**Цель:** заменить EDSM HTML-парсер новым поиском через Spansh, сохранив прежние параметры CLI без изменений.

**Архитектура:** CLI остаётся точкой входа и преобразует прежние флаги в доменные критерии. Новый use case разрешает центральную систему, ищет тела вокруг её координат, нормализует и фильтрует ответы, группирует по ID64 систем и форматирует результат.

**Стек:** Rust 2024, Tokio, reqwest, serde/serde_json, clap, thiserror.

**Спецификация:** `docs/architecture/spansh-redesign.md`.

## Глобальные ограничения

- Не использовать локальную базу, импорт EDSM dump или периодические обновления.
- Не использовать EDSM HTML scraping.
- Сохранить флаги `-S/--system`, `-P/--planet-type`, `-A/--atmosphere-type`, `-t/--temperature`, `-g/--gravity`, `-p/--pressure`, `-c/--count` и прежние default values.
- ID64 хранить как строку или u64, никогда как f64.
- Основные тесты не должны обращаться к интернету.
- Не объявлять контракт Spansh подтверждённым без живой проверки.

## Review Focus

- Ответ autocomplete содержит несколько совпадений или неизвестную обёртку JSON.
- ID64 больше 2^53 и/или приходит числом.
- Отсутствующие/null физические параметры не должны превращаться в нули.
- API возвращает повторяющиеся тела на разных страницах.
- Ошибка посреди пагинации не должна маскироваться под пустой успешный результат.
