# Интерактивное меню профилей поиска — план реализации

> **Для исполнителей:** обязательный поднавык: использовать superpowers:executing-plans (или subagent-driven-development, если будет выбран этот режим). Выполнять задачи последовательно; шаги отмечены чекбоксами.

**Цель:** добавить интерактивное меню с семью профилями и ручной настройкой при запуске без аргументов, сохранив старый CLI.

**Архитектура:** доменные критерии расширяются поддержкой нескольких типов поверхности и режима вулканизма. Семь неизменяемых профилей отделяются от терминального UI; меню собирает ввод и передаёт единый `SearchCriteria` в существующий `SearchUseCase`. Входная точка различает пустой запуск и legacy CLI через `Args::try_parse()`.

**Стек:** Rust 2024, clap, tokio, std::io, serde_json; новых зависимостей нет.

**Спецификация:** `docs/superpowers/specs/2026-11-20-search-presets-menu-design.md`

## Глобальные ограничения

- Старые флаги `-S/--system`, `-P/--planet-type`, `-A/--atmosphere-type`, `-t/--temperature`, `-g/--gravity`, `-p/--pressure`, `-c/--count` и `--exclude-with-bio-signals` сохраняют поведение.
- Температура передаётся и сравнивается в Кельвинах, без конвертации.
- Радиус остаётся 1000 св. лет; landable и mapped критерии не меняются.
- Не добавлять зависимости.
- Максимум видов и потенциальная стоимость — справочные ориентиры, не фильтры и не гарантии.
- Неизвестное значение вулканизма не трактовать как отсутствие вулканизма или как водную магму/гейзеры.

## Review Focus

1. Отсутствующее или неизвестное поле вулканизма не должно ошибочно пропускать планету для ограниченного профиля — тест в задаче 1.
2. Профиль с двумя типами поверхности должен принимать оба и отклонять остальные — тест в задаче 1.
3. Пустой ввод, EOF и неверный пункт меню не должны вызывать panic или бесконечный цикл — тесты в задаче 4.
4. `--help` и `--version` не должны запускать меню — тест в задаче 5.
5. Ручная настройка и legacy CLI должны одинаково валидировать диапазоны и сохранять defaults — тесты в задачах 3 и 5.

### Задача 1. Расширить доменные критерии несколькими типами поверхности и вулканизмом

**Файлы:**
- Изменить: `src/domain/criteria.rs`
- Изменить: `src/spansh/query.rs`
- Изменить при необходимости: `src/domain/body.rs`
- Тесты: встроенные unit-тесты указанных модулей и fixtures существующих интеграционных тестов

**Интерфейсы:**
- `SearchCriteria` должен хранить допустимые типы поверхности как набор канонических строк; legacy `from_cli(planet_type: &str, ...)` сохраняет сигнатуру и переводит одиночный тип в одноэлементный набор.
- Добавить конструктор для нескольких типов поверхности и типизированный режим вулканизма: без ограничений, без вулканизма, водная магма и гейзеры.
- `matches(&Body)` применяет все ограничения; для ограниченного режима отсутствие/неизвестный volcanism возвращает false.

- [ ] **Шаг 1: Добавить падающие тесты критериев**
  - Два subtype принимаются для профиля multi-type; третий отклоняется.
  - `None`, пустая строка и неизвестная строка volcanism отклоняются для обоих ограниченных режимов.
  - Без ограничений принимаются тела с любым volcanism.
  - Подтверждённые строки без вулканизма и водной магмы/гейзеров принимаются только соответствующим режимом.
- [ ] **Шаг 2: Запустить адресные тесты и убедиться, что они падают** — `cargo test domain::criteria`.
- [ ] **Шаг 3: Реализовать набор subtype и enum режима вулканизма** в `src/domain/criteria.rs`; сохранить legacy `from_cli` и добавить конструктор для нескольких типов.
- [ ] **Шаг 4: Проверить реальные значения volcanism из доступных Spansh fixtures/ответов и закрепить их тестами.** Не добавлять предположительные варианты как подтверждённые. Если контракт не подтверждает однозначное распознавание «водная магма и гейзеры», соответствующий режим должен безопасно возвращать false и сообщать пользователю, что фильтр не может быть применён, пока контракт не уточнён.
- [ ] **Шаг 5: Добавить серверный subtype filter с массивом значений** в `src/spansh/query.rs`; локальная проверка остаётся обязательной.
- [ ] **Шаг 6: Запустить** `cargo test domain::criteria` и `cargo test spansh::query`; все тесты должны пройти.
