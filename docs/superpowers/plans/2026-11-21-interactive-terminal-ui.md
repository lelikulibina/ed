# Интерактивный TUI на Ratatui — план реализации

> **Для исполнителя:** обязательно использовать `superpowers:executing-plans` и `superpowers:test-driven-development`; выполнять задачи последовательно с TDD.

**Цель:** заменить построчный ANSI-опросник на полноэкранный интерактивный интерфейс Ratatui + Crossterm, сохранив существующий поиск и CLI.

**Архитектура:** presentation layer получает из каталога пресетов данные и поддерживает независимую модель состояния интерфейса. Модель формы преобразуется в существующий `SearchCriteria` только после успешной валидации. После подтверждения `main.rs` передаёт выбор прежнему `SearchUseCase`; сетевой поиск и вывод результатов не переписываются.

**Стек:** Rust 2024, Ratatui, Crossterm, существующие anyhow/Clap/Tokio; тестируемая state machine без реального терминала.

**Спецификация:** `docs/design/interactive-terminal-ui.md`.

## Глобальные ограничения

- CLI с аргументами остаётся прежним; `--help` и `--version` не открывают TUI.
- Без аргументов TUI запускается только при интерактивных stdin и stdout.
- Температура задаётся в K, давление — в atm, гравитация — в g.
- Пресеты сохраняют точные числовые границы и стандартную гравитацию 0.1–1.0 g.
- Для профиля 3 типы поверхности являются альтернативами OR.
- Вулканизм не является критерием поиска ни в одном пресете.
- Число дорогих видов и потенциальная стоимость — только справочная информация.
- Исключение тел с зарегистрированными биосигналами — независимый переключатель.
- Не менять алгоритм поиска, разрешение центральной системы, пагинацию Spansh и формат результатов.
- На ширине терминала менее 90 колонок интерфейс переключается на вертикальную компоновку.
- Raw mode, alternate screen и видимость курсора должны восстанавливаться при штатном выходе и ошибках.

## Review Focus

- Размер терминала меньше минимально ожидаемого: интерфейс показывает понятное сообщение/компактную раскладку, не паникует и не обрезает критические действия.
- Вставка Unicode и редактирование поля: курсор и удаление работают по символам, не повреждая UTF-8.
- Пустая или некорректная система, нулевой count и обратные диапазоны: запуск блокируется, введённые значения остаются доступны для исправления.
- Ошибка инициализации терминала или чтения события: terminal guard восстанавливает raw mode, alternate screen и курсор.
- Esc/выход на разных экранах: несохранённая форма не запускает поиск и не теряет выбранный пресет без понятного перехода назад.

### Задача 1. Модель состояния и валидация формы

**Файлы:**
- Создать `src/presentation/tui/state.rs`.
- Создать `src/presentation/tui/form.rs`.
- Изменить `src/presentation/mod.rs` для модуля TUI (без подключения к main на этом шаге).
- Тесты рядом с новыми модулями.

**Интерфейсы:**
- `Screen`: `Presets`, `Manual`, `Confirm`.
- `Focus`: выбор профиля и редактируемые поля.
- `AppState`: текущий экран, выбранный индекс пресета, `SearchForm`, сообщение валидации и флаг выхода.
- `SearchForm`: система, температура, гравитация, давление, count, exclude_with_bio_signals; ручные planet_type и atmosphere_type.
- `SearchForm::from_preset(&SearchPreset) -> SearchForm`.
- `SearchForm::to_selection(&self) -> Result<TuiSelection, FormError>`.
- `TuiSelection` содержит `system: String` и `criteria: SearchCriteria`; UI не меняет доменную модель.
- Валидация числовых диапазонов использует существующие `parse_range_i32`, `parse_range_f32` и `NumericRange::new`, а count должен быть больше нуля.

### Задача 3. Ratatui/Crossterm и терминальный жизненный цикл

**Файлы:**
- Изменить `Cargo.toml` и `Cargo.lock`.
- Создать `src/presentation/tui/terminal.rs`.
- Создать `src/presentation/tui/ui.rs`.
- Изменить `src/presentation/tui.rs` на модульный фасад.
- Тесты layout/helpers там, где они не требуют TTY.

**Интерфейсы:**
- `TerminalSession::enter() -> Result<TerminalSession>`; Drop best-effort восстанавливает alternate screen, raw mode и курсор.
- `draw(frame, state)` отвечает только за отрисовку.
- `run_tui() -> anyhow::Result<Option<TuiSelection>>` возвращает None при выходе, Some только после подтверждения.
- В широкой раскладке список профилей и детали находятся рядом; при ширине менее 90 колонок панели располагаются вертикально.
- Панели: заголовок/статус, пресеты, подробности выбранного пресета, параметры запуска/ручной настройки, подсказки клавиш.
- Поля редактируются с клавиатуры; поддерживаются Unicode-ввод, Backspace, Tab/Shift-Tab, Space для переключателя, Enter для выбора/подтверждения, Esc назад, F5 запуск, q выход.
- Цвета и выделение должны оставаться читаемыми в тёмном и светлом терминале; не полагаться только на цвет для обозначения выбора.
