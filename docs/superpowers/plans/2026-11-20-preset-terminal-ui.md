# TUI выбора поисковых профилей — план реализации

> **Для исполнителей:** выполнять план последовательно, используя TDD и отмечая каждый шаг.

**Цель:** при запуске без аргументов показывать полноценный терминальный интерфейс выбора одного из семи поисковых профилей или ручной настройки, затем запускать существующий сценарий поиска.

**Архитектура:** каталог профилей и преобразование в критерии находятся в application/domain слоях. TUI на Ratatui + Crossterm отвечает только за ввод и отображение; запуск поиска и печать результатов остаются в текущем application/presentation pipeline. Старый CLI с аргументами не меняет поведение.

**Стек:** Rust 2024, Clap, Tokio, Ratatui, Crossterm.

**Спецификация:** `docs/design/preset-terminal-ui.md`.

## Глобальные ограничения

- Температура хранится в K, давление — в atm; значения из таблицы не пересчитывать.
- Гравитация профилей: текущий default CLI `0.1–1.0 g`.
- Максимум дорогих видов и стоимость — только справочные поля UI.
- Типы поверхности профиля 3 — альтернативы OR.
- В профилях 1–3 вулканизм означает отсутствие вулканизма; профиль 5 принимает Water Magma ИЛИ Water Geysers.
- Профили 4, 6, 7 не ограничивают вулканизм.
- Не менять поиск/резолвер/пагинацию/вывод результатов за пределами необходимых фильтров.
- `--help`, `--version` и запуск с CLI-аргументами не открывают TUI.
- В неинтерактивном stdin/stdout не включать raw mode.
- Состояние терминала восстанавливать при ошибке и штатном выходе.

## Фокус ревью

- Узкий терминал: список и детали должны оставаться читаемыми без горизонтального переполнения.
- Некорректный/пустой ввод системы и количества результатов: не запускать поиск с невалидными данными.
- Отсутствующее значение вулканизма: трактовать согласованно с фильтром «без вулканизма», не считать его доказанным отсутствием.
- Неизвестные строки Spansh для вулканизма: не отбрасывать реальные результаты молча; зафиксировать контракт отдельными тестами.
- Ошибка отрисовки/чтения клавиши: терминал должен выйти из raw/alternate screen.
