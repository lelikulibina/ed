# Дизайн интерактивного TUI выбора поисковых профилей

**Статус:** проектирование  
**Базовая ветка:** ed-dev  
**Рабочая ветка:** feature/preset-terminal-ui

## Цель

При запуске приложения без аргументов CLI показывать аккуратный интерактивный интерфейс выбора одного из семи поисковых профилей из пользовательской таблицы. После выбора запросить центральную систему и запустить существующий сценарий поиска. Существующий CLI с аргументами сохранить без изменений.

## Предлагаемый UX

### Главный экран

Использовать оформленный ANSI-интерфейс с компактным меню профилей и отдельной панелью сведений; ввод выбора и параметров выполняется построчно, без raw mode и сторонних терминальных зависимостей. Клавиши со стрелками не требуются: выбор выполняется цифрами 1–9.

- Верхняя панель: название ED: Planet Search, короткое описание и версия.
- Левая/основная панель: список семи профилей с клавиатурной навигацией ↑/↓.
- Правая панель: подробности выделенного профиля.
- Нижняя подсказка: введите номер профиля (1–7), 8 — ручная настройка, 9 — выход.
- Восьмой пункт — «Ручная настройка».
- Девятый пункт — «Выход».

Каждый профиль в списке имеет короткое имя и компактный маркер типа мира. Подробная панель показывает:
- тип поверхности;
- атмосферу;
- температуру, K;
- давление, atm;
- гравитацию (для профилей оставить существующий default 0.1–1.0 g, так как таблица не задаёт диапазон);
- вулканизм;
- справочный максимум дорогих видов;
- справочную максимальную потенциальную стоимость.

### Экран подтверждения и запуска

После подтверждения профиля:
1. Показать сводку выбранных критериев.
2. Запросить имя центральной системы.
3. Сохранить текущий default количества результатов (5), дать возможность изменить его.
4. Предложить переключатель исключения тел с уже зарегистрированными биосигналами (--exclude-with-bio-signals).
5. Запустить существующий SearchUseCase и вывести результаты текущим механизмом.

Пользователь должен иметь возможность вернуться к списку профилей до старта поиска.

### Визуальный стиль

- Сдержанная космическая палитра: тёмный фон терминала, циан/голубой акцент, приглушённые подписи.
- Выбранный профиль выделяется контрастной рамкой и маркером.
- Не полагаться на emoji как на единственный способ различить пункты.
- Корректно работать в терминалах без поддержки цвета: ANSI-цвета не обязательны для понимания меню, числовая навигация и текст остаются читаемыми.
- Не использовать графические символы там, где они ломают выравнивание в узких терминалах; минимальная ширина для двухпанельного режима — около 90 колонок, иначе переключаться на вертикальную компоновку.
- Восстанавливать состояние терминала при штатном выходе и ошибках.

### Семантика полей

- «Дорогие виды» и «потенциальная стоимость» — только справочная информация в интерфейсе. Не использовать эти числа как фильтры, гарантии находки или сортировку результатов.
- Гравитация отсутствует в пользовательской таблице. Не выдумывать диапазоны; использовать текущий CLI default 0.1–1.0 g и явно показывать его в деталях.
- Вулканизм отображается только как справочная характеристика из пользовательской таблицы. Он не используется ни в серверной, ни в локальной фильтрации: надёжность и полнота поля Spansh не подтверждены, а сведения о вулканизме могут быть доступны только для тел с совершённой высадкой.
- Для всех семи профилей вулканизм не ограничивается.
- Типы поверхности профиля 3 — два допустимых варианта (OR), а не обязательное одновременное соответствие двум типам.

## Архитектура

- Добавить отдельный модуль презентации интерактивного интерфейса, не смешивать TUI с доменной моделью.
- Каталог профилей оформить как типизированные неизменяемые данные в application/domain layer.
- TUI возвращает выбранный профиль или ручные параметры; он не выполняет сетевые запросы.
- Преобразование выбранного профиля в SearchCriteria должно происходить отдельно от отрисовки.
- CLI-путь с явными аргументами остаётся прежним. --help и --version не должны открывать TUI.
- При запуске без аргументов в неинтерактивном stdin/stdout не пытаться входить в raw mode: вывести понятную ошибку с примером CLI-вызова.
- Не менять существующий формат вывода результатов в рамках этой задачи.

## Зависимости

Дополнительные зависимости не требуются: интерфейс использует ANSI escape sequences и стандартный построчный ввод. Это сохраняет lock-файл и совместимость со сборкой через `--locked`.

## Проверки

- Unit tests каталога: все 7 профилей имеют точные значения таблицы.
- Unit tests преобразования профилей в критерии: диапазоны, типы поверхности OR, атмосфера; отсутствие фильтра вулканизма.
- UI tests на переходы выбора, подтверждения, возврата, выхода и ручной настройки.
- Проверить отсутствие изменения старого CLI: короткие/длинные флаги, defaults, --help, --version.
- Проверить терминальную очистку при обычном выходе и ошибке.
- cargo fmt -- --check, cargo clippy --locked --all-targets --all-features -- -D warnings, cargo test --locked --all-targets.

## Вне рамок

- Изменение алгоритма поиска Spansh, resolver и пагинации.
- Изменение справочника или алгоритма оценки экзобиологии.
- Пересмотр единиц измерения.
- Изменение структуры или стилистики вывода результатов поиска.
