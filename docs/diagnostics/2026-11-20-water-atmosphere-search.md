## Диагноз

1. Серверный поиск не ограничивается единственной строкой `Water`: он запрашивает labels, которые нормализуются к CLI-категории Water, включая `Thin Water`, `Thick Water`, `Hot Water`, `Hot thin Water`, `Hot thick Water` и `Suitable for water-based life` (согласно фактическому payload теста).
2. Live-ответ содержит 125 landable Rocky bodies с нормализованной атмосферой `Water`. Следовательно, гипотеза «Spansh вообще не возвращает водные планеты» опровергнута для этого центра/радиуса.
3. Ноль результатов при полном профиле вызван дополнительными ограничениями температуры/давления/гравитации. В выборке первых 15 давление и гравитация не проходят профильные границы. Это образцы первой страницы, а не полный анализ всех 125 строк; нельзя утверждать, что каждый из 125 нарушает каждую границу.
4. `Water-rich` остаётся отдельной категорией и намеренно не смешивается с `Water`.
5. Текущая диагностика не доказывает, что все системы и все атмосферные labels Spansh покрыты; она подтверждает только проверенный запрос вокруг Drojia.

## Что не менять без отдельного решения

- Не переводить температуру из Kelvin: значения сравниваются в K.
- Не расширять давление или гравитацию автоматически.
- Не объединять `Water-rich` с `Water` без подтверждения требований.
- Не убирать `is_landable=true` без отдельного решения о поиске неландируемых тел.

## Следующий корректный шаг при необходимости

Если требуется найти планеты, соответствующие именно профилю из таблицы, нужно отдельно согласовать диапазон гравитации для этого профиля (сейчас CLI подставляет default 0.1–1.0 g, если параметр не указан) и сохранить диапазон давления 0.040–0.063 atm. Затем повторить один целевой live-запрос. Не менять общие defaults ради одного профиля.
