# План тестирования Spansh-перехода

## Принципы

Основной CI не зависит от доступности Spansh. Все текущие fixtures синтетические и описывают предполагаемую форму ответов; называть их реальными ответами Spansh нельзя до live-проверки. Сетевые smoke-тесты отдельные, ограниченные по времени и не обязательны для каждого push. Не загружать полный EDSM dump.

## Unit-тесты

### Валидация аргументов и доменных диапазонов
- min < max, min == max, min > max;
- отрицательные значения там, где запрещены;
- NaN/Infinity;
- пустые/пробельные имена систем;
- count = 0 и предельные значения;
- единицы измерения температуры, давления, гравитации и расстояния.

### Разрешение системы
- точное совпадение;
- несколько кандидатов с одинаковым/похожим именем;
- fallback удаляет последний компонент имени по одному;
- первое совпадение выбирается детерминированно;
- пустой ответ, некорректный JSON, отсутствующие координаты;
- координаты 0, отрицательные значения и большие значения;
- ID64 больше 2^53 сохраняется без потери точности.

### Построение запроса
- reference_coords равны координатам исходной системы;
- радиус включён и не подменяется distance_to_arrival;
- каждый тип фильтра сериализуется в ожидаемую форму;
- Any/отсутствующий фильтр не создаёт ошибочное ограничение;
- size/page и sort имеют корректные значения;
- сериализованный payload сравнивается с golden fixture.

### Нормализация и фильтрация
- все nullable поля: null, отсутствуют, корректные значения;
- точные min/max включены;
- значение за границей исключено;
- неизвестные enum значения не вызывают panic;
- mapped/unmapped и landable;
- дубли по ID64 удаляются, одинаковые имена с разными ID64 сохраняются;
- группировка идёт по system_id64, а не system_name.

### Пагинация
- одна страница;
- несколько страниц;
- пустая последняя страница;
- отсутствие search_reference;
- повтор страницы/повтор тела;
- сервер сообщил total, но выдаёт меньше;
- ошибка посередине — ошибка/частичный результат, но не ложный успех;
- защитный максимум страниц предотвращает бесконечный цикл.

### HTTP client
- 2xx JSON;
- 400 не ретраится;
- 429 ретраится с backoff;
- 5xx ретраится ограниченно;
- сетевой timeout/обрыв ретраится;
- исчерпание попыток возвращает исходную классифицированную ошибку;
- semaphore ограничивает concurrency;
- base URL можно заменить на локальный тестовый сервер.

## Fixture integration tests

В `tests/fixtures/spansh/` хранить обезличенные/минимизированные ответы:
- system autocomplete exact;
- system autocomplete с несколькими вариантами;
- body search page 0;
- body search следующая страница или recall;
- пустой поиск;
- тело с nullable-полями;
- тело с ID64 больше 2^53;
- ответы ошибок 400/429/5xx (если полезно для контрактов).

Проверять полный сценарий: имя -> координаты -> запрос тел -> страницы -> нормализация -> локальные критерии -> группы систем. Тест не должен открывать сеть.

## Живые smoke-тесты (ручные/отдельный workflow)
- Resolve известной системы с координатами.
- Запрос 1 LY и 50 LY; сравнить расстояния и число систем.
- Запрос с узким subtype и с несколькими subtype.
- Проверить, что system_x/y/z у тела соответствуют системе.
- Проверить pagination на поиске с большим числом совпадений.
- Проверить поведение /save и recall, если direct POST не возвращает данные.
- Замерить latency и заголовки rate-limit; не делать нагрузочного тестирования.
- Сохранять только небольшие fixtures, не весь ответ/дамп.

## Команды и критерии CI

- `cargo fmt -- --check`
- `cargo clippy --locked --all-targets --all-features -- -D warnings`
- `cargo test --locked --all-targets`
- Никакие unit/fixture tests не требуют интернета.
- Smoke tests запускаются отдельным workflow по `workflow_dispatch` или commit marker `[spansh-live-smoke]`; текущий live probe подтверждает POST `/api/bodies/search` с Sol coords/radius=1/page size=5 (HTTP 2xx, 5 parseable rows, no recognized GUID). Page=1 behavior is being probed separately.
- Live workflow does not run on ordinary commits; network smoke remains outside required CI.


## Фактическое покрытие текущей реализации

Реализовано и покрыто тестами:
- старые короткие/длинные CLI-флаги и значения по умолчанию;
- валидация числовых диапазонов и нормализация прежних значений типов планет/атмосферы;
- ID64 в строковой форме и числовой u64 без преобразования в f64;
- разбор координат системы и вложенного родительского объекта;
- exact match имени системы, затем fallback по удалению конечных компонентов;
- построение payload с reference_coords и расстоянием;
- mock-server проверка POST поиска тел, recall следующей страницы и локальных фильтров;
- полный mock-сценарий resolver -> body search -> критерии;
- HTTP retry для 5xx и интервал между запросами.

Пока не реализовано/не подтверждено:
- живой контракт Spansh для POST /api/bodies/search и фактические названия всех полей;
- живая семантика recall GUID/page и точный индекс первой recall-страницы;
- проверка повторяющейся страницы отдельным тестом (есть дедупликация тел и защитный предел страниц);
- отдельные тесты для 400, 429, исчерпания retry и ошибки посередине пагинации;
- подтверждение единиц измерения surface_pressure/gravity в ответе Spansh;
- живой smoke test. До его выполнения схема запроса и DTO остаются provisional.
