# План восстановления парсера EDSM

## Цель
Вернуть поиск планет без зависимости от HTML-страниц EDSM, которые могут быть заменены Cloudflare Challenge.

## Решение
Поиск переведён на официальный JSON API EDSM:
1. `/api-v1/sphere-systems` получает системы в радиусе 100 световых лет от указанной опорной системы.
2. `/api-system-v1/bodies` получает тела каждой найденной системы.
3. Фильтрация выполняется локально по типу планеты, атмосфере, гравитации, температуре и давлению.
4. HTTP-слой проверяет статус, Content-Type и Cloudflare Challenge до разбора ответа.
5. Запросы тел ограничены параллелизмом 4 и интервалом 500 мс после каждого запроса.

## Ограничения API и осознанные компромиссы
- API EDSM ограничивает радиус `sphere-systems` значением 100 св. лет; поиск ограничен этим радиусом.
- Один пакет обрабатывает до 10 систем; `max_pages = 100` ограничивает один запуск первыми 1000 системами, отсортированными по расстоянию.
- Документированная модель EDSM API содержит поле `discovery`, но не документирует статус картографирования (`isMapped`). Поэтому программа не может надёжно исключить уже закартографированные планеты. Если API не возвращает `isMapped`, такие планеты включаются в результаты, а CLI выводит предупреждение. Не подменяем статус картографирования статусом первооткрывателя.
- EDSM API возвращает гравитацию в м/с² и давление в паскалях. Программа переводит их в привычные CLI-единицы: земные g и атмосферы.
- Известные ограничения частоты запросов учитываются консервативным ограничением параллелизма и паузой. При HTTP 429/403 поиск прекращается с явной ошибкой, а не маскирует её пустым результатом.

## Изменения
- `src/parser/core.rs`: единый HTTP-клиент, таймауты, проверка HTTP-статусов/Content-Type, обнаружение Cloudflare для HTML и JSON.
- `src/parser/search.rs`: поиск систем через Sphere Systems API, загрузка тел через System API, фильтрация API-данных и ограничение частоты запросов.
- `src/parser/planet.rs`: преобразование JSON-тел в доменную модель и конвертация единиц измерения.
- `src/main.rs`: использование результатов API и предупреждение о недоступном статусе картографирования.
- `Cargo.toml` / `Cargo.lock`: прямая зависимость от `serde_json` и Tokio time.
- Unit-тесты покрывают конвертацию единиц, исключение звёзд/неландируемых тел и основные фильтры поиска.
