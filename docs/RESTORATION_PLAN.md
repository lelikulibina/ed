# План восстановления парсера EDSM

## Цель
Вернуть поиск планет без зависимости от HTML-страниц EDSM, которые могут быть заменены Cloudflare Challenge.

## Решение
Основной поиск переведён на Spansh API:
1. Координаты опорной системы запрашиваются у EDSM через `/api-v1/system` и резервно через `/api-v1/systems?systemName[]=...`; если система отсутствует в EDSM, выполняется поиск через Spansh autocomplete `/api/search?q=...` и загрузка найденной системы через `/api/system/{id64}`.
2. Spansh `POST /api/systems/search` возвращает соседние системы, отсортированные по расстоянию от координат центра.
3. Для каждой найденной системы загружается список тел через `GET /api/system/{id64}`, затем полные параметры каждой планеты через `GET /api/body/{id64}`; фильтры применяются к подробным данным, а в результат записывается имя её реальной системы.
4. Обход продолжается страницами до конца выдачи или выхода за радиус 2500 св. лет. Лимит `-c N` ограничивает число совпадений, а не число просмотренных систем. Произвольного ограничения страниц нет.
5. HTTP-слой проверяет статус, Content-Type и Cloudflare Challenge до разбора ответа; временные ошибки повторяются с backoff.

## Ограничения API и осознанные компромиссы
- EDSM `sphere-systems` и `cube-systems` возвращали HTTP 503 при проверке из GitHub Actions. Список соседних систем и их тела поэтому загружаются из Spansh.
- Система `Boeft QP-R c7-41` не находится ни в EDSM System API, ни в Spansh autocomplete. Без её координат нельзя честно выполнить сценарий с этой опорной точкой. Для проверки самого обхода систем CI использует индексированную систему Sol; для проверки Boeft нужны координаты X/Y/Z из игры или другого достоверного источника.
- Данные Spansh не предоставляют подтверждённый статус картографирования (`is_mapped`). Поэтому программа не может надёжно исключить уже закартографированные планеты. Неизвестные статусы включаются в результаты, а CLI выводит предупреждение. Не подменяем статус картографирования оценочной наградой за картографирование.
- Spansh возвращает гравитацию в земных g, давление в атмосферах и температуру в K; дополнительные конвертации не нужны.
- Для временных ответов 429/502/503/504 предусмотрены три повтора с экспоненциальной задержкой и поддержкой Retry-After в секундах. При пагинации Spansh выдерживается пауза в одну секунду. После исчерпания попыток ошибка показывается явно.

## Изменения
- `src/parser/core.rs`: единый HTTP-клиент, таймауты, проверка HTTP-статусов/Content-Type, обнаружение Cloudflare для HTML и JSON.
- `src/parser/search.rs`: получение координат с резервированием EDSM/Spansh, обход соседних систем через Spansh `systems/search`, исключение опорной системы из результатов, загрузка полных записей планет через `/api/body/{id64}`, ограничение радиусом 2500 св. лет и фильтрация планет.
- `src/parser/planet.rs`: преобразование JSON-тел Spansh в доменную модель.
- `src/main.rs`: использование результатов API и предупреждение о недоступном статусе картографирования.
- `Cargo.toml` / `Cargo.lock`: прямая зависимость от `serde_json` и Tokio time.
- Unit-тесты покрывают разбор Spansh body-search, исключение звёзд/неландируемых тел, политику повторов и основные фильтры поиска.
